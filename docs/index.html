GlowUp TV

Tout ce que Home Assistant, ou un petit script JS, peut lire et envoyer sur l'écran d'accueil de la TV. Pensé pour la mise en page Aura, avec les deux autres (Épuré, Widgets) en comparaison.

Combien de notifications en même temps ?

Une « notification » est un widget déclaré dans la config de la TV, placé dans une zone de la mise en page. Chaque zone a un maximum : au-delà, la TV refuse la config (400), elle ne tronque pas en silence. À cela s'ajoute le toast, message passager sur l'accueil.

Un widget ne se place qu'à un seul endroit par mise en page. Quand son ttl est écoulé, on_expire décide : hide le masque, stale le grise avec l'heure de dernière mise à jour, keep le laisse. En Aura, ce qui ne tient pas dans les 440 px de haut de la colonne reste dehors.

Le nombre de widgets différents que tu peux déclarer n'est pas plafonné par la doc : c'est le placement par zone qui limite ce qui s'affiche.

Les informations que je peux envoyer

Le contenu doit correspondre au type du widget déclaré dans la config. Champ commun : ttl (secondes, 0 = jamais, 604 800 au plus). Un champ inconnu est refusé.

TypeChampsExemple
chiptext, icon, color« Porte du garage ouverte », « Colis livré »
statvalue, unit, label, secondary, trend (up down flat)21,4 ° · Salon · Humidité 48 %
progresslabel, value (0 à 100), text, detail AuraBambu 1 · 62 % · reste 1 h 34 · « couche 142/230 »
listitems : [{text, secondary, icon}] (max_items de la config)Les prochains rendez-vous. En Aura : seul le 1er est affiché
imagecamera_entity (HA) ou data base64, captionInstantané de caméra, 1 Mo au plus, jamais une URL

Couleurs et icônes

color : accent, ok, warning (disque ambre plein en Aura, passe en premier), alert, muted, ou #RRGGBB. icon : mdi:… parmi 163 icônes embarquées (domotique et réglages, liste dans tools/glowup_icons.py de glowup-tv) : le sous-ensemble est limité, vérifie la liste avant d'utiliser une icône rare.

Générateur

Remplis le formulaire : tu obtiens l'action Home Assistant, la commande du script JS, le curl et le JSON brut.

Rien n'est envoyé à la TV depuis cette page : le navigateur ne peut pas l'appeler (voir Limites).

Les informations que je peux lire

GET /healthla TV répond (sans token)
GET /infoversion, boot_id (change au redémarrage du launcher), appareil, Android, profil, écran, mises en page, capacités
GET /configconfig complète + revision : mise en page, zones, widgets déclarés, thème, horloge, dock
GET /statephoto de l'état poussé (widgets affichés), pour déboguer
GET /appsapps lançables : package, label
GET /wallpapersfonds stockés sur la TV

Côté Home Assistant : 4 entités par TV

En lignebinary_sensor : la TV répond (vérifié toutes les 60 s)
Versionsensor de diagnostic : version du launcher
Mise en pageselect : lit et change la mise en page (options = layouts de /info)
Fondselect : fond parmi ceux de la TV

Dans l'interface HA, le sélecteur de glowup.set_layout ne propose que epure et widgets (voir services.yaml) : pour Aura, tape aura en mode YAML ou utilise l'entité « Mise en page ». À vérifier sur ta TV : la liste layouts de /info dit ce qu'elle accepte.

Le script JS

tools/glowup.mjs : un client et un CLI Node 18+, sans dépendance. Il parle directement à la TV. La commande status montre, pour la mise en page active, combien d'emplacements sont affichés, placés et au maximum.

# 1. Appairage : Réglages TV > Appairer un appareil, puis le code à 6 chiffres
GLOWUP_HOST=192.168.1.50 node tools/glowup.mjs pair 123456
# 2. Garde le token renvoyé dans ton environnement (ne le commite pas)
export GLOWUP_HOST=192.168.1.50 GLOWUP_TOKEN=...
node tools/glowup.mjs status
node tools/glowup.mjs toast "Le café est prêt" mdi:bell 6
node tools/glowup.mjs set garage '{"text":"Porte ouverte","icon":"mdi:garage-open","color":"warning"}' 1800
node tools/glowup.mjs layout aura
node tools/glowup.mjs demo

En module :

import { GlowUp } from "./tools/glowup.mjs";
const tv = new GlowUp("192.168.1.50", process.env.GLOWUP_TOKEN);
console.log(await tv.info());
await tv.setWidget("imprimante_1", { label: "Bambu 1", value: 62, text: "reste 1 h 34", detail: "couche 142/230" });

Limites à connaître

Corps JSON64 Ko au plus, imbrication 32 niveaux
Débit20 requêtes/s par client, au-delà 429
Image d'un widget1 Mo au plus (base64), décodée sur la TV
TTL7 jours au plus ; HA ne renvoie un contenu identique qu'à la moitié du ttl
Toast / lancement d'appaccueil affiché seulement : sinon shown: false ou 409 blocked_by_android (Shield, Android 10+)
Dock1 à 12 apps
Pas dans l'APIcommande shell, installation d'app, lecture d'écran, simulation de touches
Réseaulocal seulement ; aucun en-tête CORS et Host vérifié, donc pas d'appel depuis une page web
Pas encoreglowup.set_wallpaper, événement glowup_widget_pressed
